# DESIGN

## 1. Как отменяются устаревшие запросы

Главный файл: `src/countrySearch.ts`, класс `CountrySearch`. Он хранит `AbortController` текущего запроса.

Как это работает:

- Каждый раз, когда пользователь меняет текст в поле, вызывается `input(query)`. Он сразу вызывает `abort()` для предыдущего запроса. Это происходит ещё до debounce, поэтому старый ответ не успеет прийти и показаться под новым текстом.
- Когда debounce срабатывает, `search(query)` создаёт новый `AbortController` и передаёт его `signal` в `searchCountries`, а оттуда в `fetch`. Браузер по-настоящему обрывает запрос, в Network он помечен как `canceled`.
- В `catch` ошибка `AbortError` (мы сами отменили) игнорируется, пользователю ничего не показывается.
- Настоящие ошибки (`TimeoutError`, `HttpError`, обрыв сети) показываются как ошибка с кнопкой «Повторить».
- 404 это не ошибка: `searchCountries` возвращает пустой массив, и показывается «Ничего не найдено».
- Таймаут сделан через `AbortSignal.any([signal, AbortSignal.timeout(ms)])`. Это один сигнал из двух: отмена по вводу и таймаут. Их можно различить: отмена даёт `AbortError`, а таймаут `TimeoutError`.

**Почему не просто флаг «это актуальный ответ?»**

Флаг только прячет проблему на экране. Старый запрос при этом продолжает идти: тратит трафик, нагружает сервер, ответ всё равно приходит и разбирается. `abort()` останавливает запрос сразу. После отмены старый промис точно завершается ошибкой и уже не может изменить экран. Это проверяет тест `src/searchRace.test.ts`: в нём мок реагирует на `signal` и отклоняет промис с `AbortError`.

## 2. Почему задержка debounce 300 мс

Значение лежит в константе `DEBOUNCE_DELAY_MS` в файле `src/main.ts`.

Люди обычно делают паузу между буквами 100-250 мс. Поэтому при наборе 300 мс запросы не уходят, а когда человек остановился, поиск начинается почти сразу.

- **Если убрать debounce или поставить очень мало (50-100 мс):** запрос будет уходить почти на каждую букву. Нагрузка на API вырастет, будет много отмен, а интерфейс будет мигать «Загрузка...».
- **Если поставить очень много (1000 мс и больше):** запросов станет меньше, но после остановки набора придётся долго ждать, и поиск будет казаться зависшим.

Отмена предыдущего запроса от задержки не зависит: она срабатывает сразу при вводе.

## 3. Сложность (Big O)

Функция `mapCountryResponse` (`src/mapCountryResponse.ts`) работает за **O(L + C + B)**, где L, C и B это количество языков, валют и границ у страны.

Почему так: простые поля (название, столица, регион, население) читаются за O(1). Каждый массив (языки, валюты, границы) проходится один раз через `map` или копирование. Для списка из N стран получается O(N · (L + C + B)). Памяти нужно столько же, потому что результат это новый объект, а не ссылка на исходный.

## 4. Принципы чистого кода

- **Каждый файл отвечает за одно.** `debounce.ts` откладывает вызов, `searchCountries.ts` ходит в сеть, `mapCountryResponse.ts` преобразует данные, `countrySearch.ts` управляет состоянием и отменой, `main.ts` рисует страницу.
- **Чистая функция.** `mapCountryResponse` не меняет входные данные и не ходит в сеть, поэтому её легко тестировать на готовом JSON.
- **Зависимости передаются снаружи.** `CountrySearch` получает функцию поиска и колбэк через конструктор (`src/countrySearch.ts`). Поэтому в тестах вместо сети подставляется мок, а логика не зависит от DOM.
- **Понятные имена, без «магических чисел».** `DEBOUNCE_DELAY_MS` в `main.ts`, `DEFAULT_TIMEOUT_MS` и `COUNTRIES_URL` в `searchCountries.ts`.
- **Состояния описаны типом.** `SearchState` в `countrySearch.ts` это одно из пяти: idle, loading, results, empty, error. `switch` в `render` проверяется TypeScript, пропустить состояние нельзя.
- **Своя ошибка.** `HttpError` (`src/httpError.ts`) хранит статус ответа. Ошибки различаются через `instanceof` и `name`, а не по тексту сообщения.
- **Безопасный вывод.** Весь динамический текст вставляется через `createElement` и `textContent`, без `innerHTML`.
